# 额度总览标准任务

用途：M1 场景走查，以及 M3 种子用户的“是否看得懂”测试。每个任务对应一张固定的演示卡片，答案由 `Tests/IslandCoreTests/DemoScenariosTests.swift` 校验，和应用实际显示保持一致。

## 打开演示数据

先退出正在运行的 Swapling，再在终端运行（不会读取或修改真实额度、设置和登录）：

```bash
dist/Swapling.app/Contents/MacOS/Swapling --demo
```

面板会自动打开并保持展开。只看部分卡片时，加 `--demo-cards`，后面写卡片名称里的关键词，用逗号分隔：

```bash
dist/Swapling.app/Contents/MacOS/Swapling --demo --demo-cards 5小时,周额度,两者
```

测完按 Esc 或 Ctrl-C 退出，再正常打开 `dist/Swapling.app`。演示时间相对于启动时刻，面板底部写着“演示数据（--demo），不是真实额度”。

## 任务与标准答案

问题统一为：**这个平台现在能不能用？受限的是哪个额度？什么时候能再用？**

| 卡片 | 状态 | 标准答案 |
| --- | --- | --- |
| Codex（正常） | 额度正常 | 能用；首层是 Session（Weekly 用了 41%，未过提醒线，不顶替）；下一项额度重置是 Session，约 3.5 小时后 |
| Claude（接近上限） | 接近上限 | 能用，但 Session 已过第一条提醒线（默认 80%）；Session 约 1.2 小时后重置 |
| Claude（5小时用完） | 额度受限 | 不能用；Session 用完；限制预计约 1.5 小时后解除 |
| Claude（周额度用完） | 额度受限 | 不能用；Weekly 用完。Session 2 小时后重置也没用，要等 Weekly 约 40 小时后重置 |
| Claude（两者用完） | 额度受限 | 不能用；两个都用完，取较晚的 Weekly（约 30 小时后），不是 Session 的半小时 |
| Claude（仅模型受限） | 部分受限 | 除 Opus 外仍可用；Opus 约 20 小时后重置；应用不给出平台整体的解除时间 |
| Codex（重置时间未知） | 额度受限 | 不能用；Session 用完，但不知道何时重置；应用不推断恢复时间 |
| Codex（读取失败沿用） | 待确认 | 不知道：本次读取超时，显示的是 20 分钟前的数据（变灰）；下一步点“重试” |
| OpenAI（未登录） | 待确认 | 不知道：没有登录或登录失效；下一步打开登录页后重试 |
| OpenRouter | 按余额 | 按余额计费，余额约 12 美元；没有百分比额度 |

## 判定建议

- M1 走查：每张卡片都能在首层找到状态、受限的额度和时间，不需要展开详情；“下一项额度重置”和“限制预计解除”不混淆。
- 种子用户测试：5 秒内答对且没有把已用、剩余读反，即算理解正确；分母为实际完成该任务的人数。
